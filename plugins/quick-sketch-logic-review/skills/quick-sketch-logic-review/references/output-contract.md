# 输出合同

## 自然语言顺序

1. **模式与目标**：模式、评审目标、判断依据和置信度。
2. **方案逻辑还原**：问题、对象、策略、实现、效果、不确定项。
3. **总体判断**：一至三句话。
4. **最高优先级问题**：默认三条，按严重度和影响排序。
5. **模块 Review**：每个模块保留一至三条高价值判断。
6. **外部事实核验**：只放会改变结论的证据、状态与限制。
7. **纸面证据**：使用与输入模式匹配的措辞。
8. **实现硬伤**：无则明确写“未发现足以击穿方案的硬伤”。
9. **下一步最小修改**：按执行顺序列出。
10. **可复用优点**：`final_sheet` 或 `benchmark` 默认包含。

## 逻辑还原模板

- 问题：谁在什么场景中，因为什么障碍，产生什么后果。
- 对象：该人群的关键约束与冲突。
- 策略：依据什么前提，通过什么机制改变什么。
- 实现：哪些角色通过哪些核心功能完成策略。
- 效果：方案声称产生什么近端与远端变化。
- 不确定项：只能推测、不可读或尚未呈现的内容。

## Finding 格式

```text
【严重度｜类别｜置信度】标题
依据：当前材料中的可见证据；必要时另列外部证据摘要。
判断：为什么削弱逻辑或击穿实现。
最小修复：一个优先动作。
纸面形式：一句话、小流程、对比图、角色关系图或输入—处理—输出图。
```

`fatal` 和 `major` 必须有具体 `minimal_fix`。`minor` 可在没有行动价值时省略。

## 三模式必含

### text_concept

- 正式图面最低呈现清单
- 建议优先画出的逻辑链
- 仍需核验的高影响事实

### board_draft

- 当前可读内容
- 未呈现内容
- 不可读内容
- 最小补图
- 可删除或压缩内容

### final_sheet

- 阅卷阅读路径
- 逻辑失败、表达失败、取舍失败
- 重画优先级
- 可复用优秀表达

## 结构化报告

若用户要求 JSON，遵守 `schemas/review_report.schema.json`。结构化报告至少包含：

- `input_mode`
- `review_goal`
- `mode_basis`
- `scheme_model`
- `visible_evidence`
- `overall_judgment`
- `findings`
- `external_fact_checks`
- `next_actions`
- `mode_specific`

生成后运行：

```bash
python scripts/validate_report.py report.json
```

## 禁止项

- 不输出单一总分或模块平均分替代诊断。
- 不把检索内容写成纸面已呈现。
- 不把不可读写成未呈现。
- 不把缺少完整商业/技术规划直接判成失败。
- 不使用“加强调研”“丰富画像”“完善方案”等无具体动作的修复。
