# 规则目录

## 1. 问题模块

| ID | 检查 | 失败信号 |
|---|---|---|
| P-F1 | 现实存在 | 只有设计者想象，找不到案例、研究、讨论或替代方案 |
| P-F2 | 重复性 | 仅依赖单个极端事件 |
| P-F3 | 后果性 | 只说“不方便”，没有损失、风险或负担 |
| P-F4 | 现有缺口 | 忽略成熟方案或未说明当前应对为何不足 |
| P-F5 | 可设计性 | 把宏观背景直接当设计问题，没有可改变变量 |

最低纸面证据：对象、具体场景、失败步骤、后果、现有应对及缺口、至少一条现实锚点。

判定：

- 核心问题与可靠事实冲突：`fatal / fact_error / broken`。
- 问题真实但缺场景、后果或缺口：`major / paper_gap / weak`。
- 只有宏观背景、无可设计变量：`major / logic_break`。

## 2. 对象模块

| ID | 检查 | 失败信号 |
|---|---|---|
| U-F1 | 真人存在 | 找不到多个独立案例，或全是营销内容 |
| U-L1 | 对象与问题一致 | 对象像为方便画人物而选择 |
| U-L2 | 特殊约束 | 只有年龄、职业、性别等一般标签 |
| U-L3 | 能力边界 | 刻板化为完全无能力 |
| U-L4 | 代表性 | 用单个极端个案承担整类人群 |
| U-P1 | 纸面可识别 | 看不出该对象为何需要不同回应 |

最低标准：

- 可发现性：至少 5 个相互独立的真实个体，或同等强度证据。
- 代表性：多个案例共享情境、行为或约束。
- 区分度：至少一条特殊约束或双目标冲突。

执行对象替换测试。若对象替换后问题和策略不变，标记 `U-L2` 或“对象 → 策略”为 `weak`。

## 3. 策略模块

| ID | 检查 | 失败信号 |
|---|---|---|
| S-L1 | 前提明确 | “用户喜欢方便”等空泛假设 |
| S-L2 | 干预明确 | 只写智能化、游戏化、陪伴化 |
| S-L3 | 中间机制 | 从功能直接跳到宏大效果 |
| S-L4 | 近端变化 | 没说明行为或状态先如何改变 |
| S-L5 | 适用边界 | 忽略不适用对象或情境 |
| S-F1 | 依据真实 | 误引行业惯例、理论或技术 |
| S-P1 | 因果可见 | 只有功能列表，没有前因后果 |

理论误用检查：

1. 具体调用了理论中的哪个变量。
2. 设计元素是否真的改变该变量。
3. 理论对象、任务、文化和情境是否接近。
4. 理论名只作为标签时判 `paper_gap` 或 `weak`，不要自动判事实错误。

最低纸面表达：对象特征/规律 → 障碍 → 干预 → 中间机制 → 近端变化，可压成四至五个节点。

## 4. 实现硬伤

### 成本错配

| ID | 触发条件 |
|---|---|
| I-C1 | 支付能力弱的对象必须承担高额设备或订阅成本 |
| I-C2 | 低频需求要求长期学习或维护 |
| I-C3 | 隐私、时间或心理成本明显超过可见收益 |
| I-C4 | 简单方案可解决，却强制引入高成本复杂系统 |

### 责任错位

| ID | 触发条件 |
|---|---|
| I-A1 | 主要成本由几乎不获益的一方承担 |
| I-A2 | 将机构或专业人员应承担的风险转给普通用户 |
| I-A3 | 长期依赖志愿者、社区人员、基层人员或商家额外劳动，却无激励、资源或制度支撑 |
| I-A4 | 关键角色的职责、权限或交接关系无法判断 |

### 技术不可行

- 场景没有所需传感器、数据、权限、算力或网络。
- 输入不能支持宣称的判断类型或精度。
- 把实验室能力按稳定消费产品呈现。
- 把概率判断画成确定结论。
- 需要大量个性化数据，却没有来源和冷启动路径。

### 高风险无边界

- 医疗、心理、安全、金融：专业人员确认、分级建议或明确非诊断边界。
- 儿童、老人、残障者等敏感人群数据：最小采集、授权/监护、退出机制。
- 公共空间自动控制：人工接管、故障安全或权限限制。
- 内容审核、身份判断：申诉、人工复核或置信度表达。

缺预算、商业模型、完整架构或全部异常流程本身不是硬伤。

## 5. 跨模块连接

| 连接 | 必问问题 | 常见断裂 |
|---|---|---|
| 问题 → 对象 | 问题是否确实发生在这类人身上 | 先选议题，再随意挑好画的人群 |
| 对象 → 策略 | 是否利用对象独特约束或动机 | 换人群后策略不变 |
| 策略 → 实现 | 功能是否承载策略机制 | 策略说减压，实现只加信息 |
| 实现 → 效果 | 效果能否由实现合理导出 | 小功能直接跳到社会系统改变 |

连接规则：

- 两端都有内容但无可解释连接：`logic_break`。
- 连接可推测但纸面未明确：`paper_gap`。
- 连接依赖错误事实：`fact_error`。
- 中间步骤过度跳跃：`weak` 或 `logic_break`。

每个核心功能至少连接一条策略机制；每条策略至少回应一个问题原因或对象约束。

## 6. 快题深度

必须呈现：问题场景、对象特殊约束、核心因果、关键流程。

可压缩呈现：用户案例、理论依据、技术原理、角色关系。

通常可省略：完整文献综述、精确研发预算、完整商业模型、完整技术架构、全部异常流程。

每个主要问题最多给一个首选动作和一个备选纸面形式。局部修复应尽量在 5–15 分钟内完成；否则明确标注“方案级调整”。
