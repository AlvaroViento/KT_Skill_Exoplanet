# 通用审查规则

## 五项模型

1. **问题**：是否具体、真实，并适合通过设计介入。
2. **对象与情境**：人、组织、物、环境或其他对象是谁；问题在何时何地发生；关键约束是什么。
3. **策略**：采取什么干预；为什么它能回应问题。
4. **实现**：产品、服务、交互、空间、流程或组合载体如何执行策略；必要角色、资源和技术是否存在。
5. **结果**：实现后首先改变什么行为、状态或条件；不要把远期愿景当作直接结果。

逐项检查相邻连接：问题是否属于该对象与情境；策略是否针对问题原因或关键障碍；实现是否承载策略；结果是否能由实现合理产生。

## 优先问题

优先报告以下问题：

- 核心问题不成立或描述无法判断。
- 对象与情境过宽，导致后续策略没有明确约束。
- 重点策略没有具体作用机制。
- 功能、形态或服务触点与策略脱节。
- 输入、数据、材料、能源、角色或技术能力无法支持声称的输出。
- 主要成本、维护或责任被转移给没有能力或动机承担的一方。
- 医疗、安全、隐私等高风险判断缺少必要的人类确认或退出边界。
- 结果跨越多个中间环节，却被写成方案的直接效果。

## 严重程度

- `fatal`：核心前提错误、实现不可能或高风险边界缺失，足以使方案失效。
- `major`：关键连接断裂，方案仍可通过局部重构修复。
- `minor`：只影响理解效率或表达可信度。

默认优先写 `fatal` 和 `major`。若没有关键问题，直接说明方案基本成立，再给至多一个增强建议。

## 最小修改

让修改能由一句补充、一个小图、一段轻量流程、一次局部删改或一个主张降级完成。若必须更换核心对象、策略或实现，明确写“需要方案级调整”，不要伪装成局部优化。

示例：

- 补一条“情境 → 障碍 → 干预”的推导链。
- 把“自动诊断”降级为“风险提示”，并增加专业人员确认。
- 删除重复界面，换成一张角色责任与交接图。

## 跨专业边界

只检查当前方案实际使用的要素：工业设计可涉及材料、制造、人体与维护；服务设计可涉及参与者、触点与交接；交互设计可涉及输入、反馈、数据与权限；空间类设计可涉及行为、流线、尺度、环境和运营。不要因为某专业可能关注某项内容，就强迫所有方案补齐该项。
